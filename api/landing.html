Variant analysis and conformance checking are solved, published algorithms. What stalls process mining is everything upstream: someone has to decide which table means "invoice cleared" — and until that decision is made, nothing downstream can start.

How GenQ works

Agent drafts. Human confirms. Business self-serves.

One loop, run once per process. Deliberately not autonomous — a wrong activity definition doesn't throw an error, it produces a confident, incorrect dashboard. So a person signs off on the semantics, exactly once.

Step 01Agent

Reads the schema, drafts the model

Point it at SAP tables, Salesforce, ServiceNow, Jira or a CSV export. The agent applies domain priors, proposes the case ID, activities and timestamps — and writes the SQL.

Step 02Your expert · once

Confirms the semantics, in business language

Every choice arrives with a rationale and a confidence level. Genuinely ambiguous calls — is a case a PO, or a PO line? — become blocking questions. Nothing is built until they're answered.

Step 03Everyone

Asks its own questions

Variants, bottlenecks, conformance, rework, custom KPIs — plus plain-English questions answered with citations back to the activities and filters used.

“I mapped Invoice Cleared to RBKP rows where the posting date is set — confirm, or correct me.”

Every mapping is a versioned, human-readable spec. The generated SQL stays visible and editable. No black boxes in the data path.

Honest scope

Built for the companies the enterprise stack prices out.

GenQ is an accelerator for teams that will never buy an enterprise process-mining platform — not a replacement for one. Being specific about the boundary is how the agentic bet stays credible.

Where it fits

  • Event volumes that suit an embedded columnar engine — no distributed cluster required
  • Reasonably vanilla source systems, where the agent's domain priors hold
  • Teams that need a working model in days rather than a quarter-long modelling phase
  • Standard processes: purchase-to-pay, order-to-cash, and growing

Deliberately out of scope

  • Object-centric process mining
  • Automation and action-flow orchestration
  • Task mining and desktop capture
  • ML forecasting and simulation
